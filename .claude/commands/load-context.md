## What the app is
A journal/log for knitting and crochet projects. More string/yarn crafts will be added later, so craft types are a DB table (`craft_types`), not hard-coded.

## Accounts and security

## Key schema decisions (see supabase/schema.sql)
- `profiles` row created by a trigger on `auth.users` from signup metadata; trigger also assigns the `user` role and default widgets.
- `friendships`: one row per pair; `pending` or `accepted`; decline/cancel/unfriend = delete.
- Projects, materials, status history, photos: visible to owner + accepted friends (admins with `projects.view_all` also see projects). Only the owner writes.
- `project_status_history` written by a trigger; powers the calendar and feed.
- Storage: `avatars` (public read, own-folder write), `project-photos` (private; owner + friends read, owner writes). Paths start with `<user_id>/`.
- The user already ran schema.sql. **For schema changes, add a numbered file in `supabase/migrations/` (next: 016_...) for them to run, written to be safe to re-run** - and also update schema.sql so it stays the complete current schema. Remind the user to run new migrations BEFORE pushing code that needs them (Netlify deploys on push).
- Migrations: 015_comment_mentions.sql (tagging + mention notifications); 014_private_projects.sql (is_private, read policy, count RPCs); 013_feedback_notifications.sql (feedback notifications for admins); 012_cover_photo.sql (project_photos.is_cover); 011_soft_delete_projects.sql (projects.deleted_at, read policy); 010_guest_feedback.sql (user_id nullable, guest_name/guest_email, anon insert policy); 009_admin_dashboard_feedback.sql (profiles.last_seen_at + touch_last_seen(), admin_list_users(), feedback_reports + feedback.manage permission); 008_hearts_comments_notifications.sql (project_likes, project_comments, notifications + triggers, notifications in realtime); 007_private_material_costs.sql (material_costs table, moves + drops project_materials.cost); 006_material_amount_cost.sql (project_materials.quantity + cost); 005_costs_difficulty_shopping.sql (projects.difficulty, project_materials.status + sort_order, project_costs table); 004_default_icon_yarn.sql (icon default yarn); 002_project_icon_color.sql (icon + color columns); 003_descriptions_notes_realtime.sql (projects.description, project_notes table, friendships in realtime publication).
- **Always name the foreign key when embedding profiles** (e.g. `profiles!projects_user_id_fkey(...)`): since migration 008, projects and profiles are linked several ways (owner, hearts, comments, notifications), and an unnamed `profiles(...)` embed fails with "more than one relationship was found".
- Private per-user data must go in its own owner-only table (RLS is per row, not per column), like `project_notes`.

## Mobile / app feel
- Logo = knitting swatch on two wooden needles (based on a reference image the user gave), berry swatch with lighter zigzag rows, needles `--logo-needle` / knobs `--logo-knob` per theme. Animated as ONE 15s loop (pause after the finished piece is ~6s at the user's request; percentages in index.css were rescaled for 15s) (CSS under "Logo" in index.css; every part has the same duration so they stay in sync; all smooth/linear, NO steps - the user wanted it gradual): 0-55% knit (clipPath `.logo-grow` = shape with a zigzag bottom edge sliding down from -32 to 0, so the growing edge is always zigzag; right needle rocks), 55-66% pause, 66-72% needles slide OUT ALONG THEIR OWN LENGTH (left -34px x, right +24/+24 toward its knob; user did not want them to look like they cut the piece), 72-76% live stitches fade, 74-92% frog (clipPath rect `.logo-frog` top edge moves down 34; `.logo-frog-strand` crinkly yarn moves with the top edge and trails up out of view), 92-95% strand yanked away, 94-100% needles slide back in. Reduced motion / animated={false} = finished piece, still. To check frames: pause all document.getAnimations() and set currentTime. Logo.jsx (viewBox 3 3 42 42, default size 32); static copies in public/favicon.svg + public/icon.svg -> icon-192/512.png (rendered with headless Chrome). Projects nav/tab icon = YarnBall line icon (customIcons.jsx), default project icon = yarn.
- `.app-shell` fills `100dvh`; top bar and phone bottom tab bar are fixed; only `.page-scroll` (<main>) scrolls; Layout scrolls it to top on route change.
- `overscroll-behavior: none`, safe-area insets, 16px inputs on phones (no iOS zoom), hover effects only in `@media (hover: hover)`, manifest + PNG icons for Add to Home Screen.
- Anti-zoom: on `(max-width: 760px), (pointer: coarse)` every input/select/textarea is 16px !important (iOS zooms on smaller text); `html { touch-action: manipulation }`; viewport has maximum-scale=1 + interactive-widget=resizes-content; Layout/PublicLayout add `html.app-locked` (html/body overflow hidden).
- Breakpoint for phone layout: `max-width: 760px`. Phone tab bar: Home, Projects, New (+), Friends (badge), Profile. Settings page (via Profile) holds Admin + Log out on phones.
